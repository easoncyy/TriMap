# TriMap · 光谱 Spectrum Atlas

本地运行的三张活地图原型。Next.js + TypeScript + React Flow + SQLite；无需安装独立数据库服务或配置外部模型密钥。

以「光谱」为交互主题，把领域、生态、认知三种维度组织在共享知识库中。面向「面向机器人操作的具身视觉」课程项目，当前版本用于验证网站结构与维护流程，所有初始知识均为待核实的演示样例。

## 三张地图与光谱主题

| 概念 | 在原型中的作用 |
| --- | --- |
| 滤光片 | 切换领域、生态、认知视角，保留知识焦点 |
| 色散 | 从一个节点探索同一视角中的相关知识 |
| 折射 | 沿明确的关系进入另一张地图 |
| 探索足迹 | 记录浏览路径，支持返回 |
| 棱镜（规划） | 调整筛选、展开深度与布局，探索不同映射 |

访客和维护者都可以反馈；维护者可以编辑内容与关系、审核发布和恢复历史。个人拖动只影响浏览器中的布局，不改变公共知识关系。

## 启动

需要 Node.js 24 LTS 或更新版本（使用内置 SQLite 与 TypeScript 支持）。在本目录运行：

```powershell
git clone https://github.com/easoncyy/TriMap.git
cd TriMap
npm ci
npm run dev
```

打开 http://127.0.0.1:3000 。开发服务只绑定本机。

也可以构建后运行：

```powershell
npm run build
npm run start
```

维护者入口默认口令为 `local-spectrum`。可复制 `.env.example` 为 `.env.local` 后修改 `MAINTAINER_PASSWORD`，重启服务生效。这是本地原型的共享维护身份；公开部署前需要完善登录尝试限流、正式身份管理、HTTPS、备份与部署数据库。

## 已实现

- 领域／生态／认知三种滤光片，图谱与列表、搜索和类型筛选。
- 点击节点查看详情，同图「色散」与跨图「折射」，关系说明、来源与浏览足迹。
- 拖动节点调整个人布局，浏览状态保存在当前浏览器 localStorage；不修改正式关系。
- 访客与维护者均能提交节点、关系反馈，维护者可回应。
- 维护者新增／编辑／移除节点与关系；先保存草稿，填写修改说明后发布。
- 历史内容快照可恢复到草稿，再审核发布。导出 JSON 备份。
- 响应式布局与减少动态效果设置；所有内容是结构样例，明确标为待核实。
- 图谱空间：公开图谱列表、我的图谱、新建空白图谱或复制当前已发布版本。
- 每份个人图谱独立保存节点、关系、草稿、反馈与历史；私有图谱仅归属访客和维护者可见。
- 个人内容编辑、图谱介绍与公开署名、私有／公开设置、链接分享。
- 具体问题反馈：选择节点或关系，填写问题类型、描述、修改建议；按对象或全部查看并跳转定位。
- 发布前检查节点与关系变更、待核实与无来源数量；版本记录保存变更清单。
- 轻量滤光片转场与减少动态效果支持。

## 个人图谱使用流程

### 全屏图谱与拖动连线

地图占满主工作区，顶部选择三个滤光片，底部光谱工具栏集中搜索、反馈、节点创建、布局保存与发布。点击节点／关系才展开详情；详情使用独立列，画布自动适配，点击画布空白或关闭按钮收起。窄屏详情位于画布下方。

有编辑权限时，点击底部「拖动连线」，从起点卡片右侧的 `+` 拖到目标卡片左侧连接点。底部直接显示起终点，填写关系名称与依据后「保存关系草稿」，无需打开关系弹窗。连线模式按三个维度排列全部节点，支持跨图连线；自连接不创建，已有同方向关系会进入编辑。退出模式恢复当前滤光片。发布仍需审核，拖动连线不会直接改动公开版本。

### 创建与维护

1. 打开「图谱空间」，浏览公开图谱或进入「我的图谱」。
2. 点击「创建图谱」，选择复制当前已发布内容或从空白开始；新图谱默认私有。
3. 添加／编辑节点和关系，拖动调整布局；「保存当前布局」会把个人布局加入图谱草稿。
4. 点击「审核发布」，查看变更清单并填写更新原因。图谱私有时，发布也不会改变可见性。
5. 在图谱空间的「管理当前图谱的名称与可见性」中勾选公开，其他访客才能浏览已发布版本。
6. 点击节点或连线后进入「反馈」，也可以在反馈对象下拉框中直接选择具体对象。图谱所有者和维护者可以保存回应。

身份仍为访客与维护者两类。访客通过服务端签名的 HttpOnly Cookie 识别自己创建的图谱，只有自己的图谱可编辑；维护者可以管理共享样例与其他图谱。没有额外的编辑者角色。

当前是本地原型：清除浏览器 Cookie、切换浏览器或使用另一个主机名会失去原有的个人归属身份，尚未提供账号登录、身份恢复和跨设备身份同步。建议定期导出内容备份，必要时由维护者处理。公开署名、反馈称呼与反馈内容会对能够访问该图谱的人展示。

「公开」指同一个服务实例内可发现，并不等于发布到互联网。默认仅绑定 `127.0.0.1`，不同浏览器访问同一地址可模拟不同访客；跨设备使用仍需后续部署。

## 本地数据

数据库为 `data/atlas.sqlite`，首次访问自动建表并初始化共享样例。图谱元数据、归属和可见性是独立表字段；每份图谱的知识、草稿、反馈、历史保存为事务内更新的 JSON 文档。WAL 与事务保证读改写的原子性；复杂查询与多人同时编辑冲突处理仍待后续扩展。

升级时若发现旧 `data/store.json`，会将其作为共享图谱导入；原文件保留不动。迁移只在数据库尚无共享图谱时执行，后续以 SQLite 为准。`data` 整个目录均不纳入 Git。

备份时先停止所有使用该数据库的服务，再复制整个 `data` 目录（包含可能存在的 WAL 文件）；不要仅复制运行中的主数据库文件。也可从界面导出当前有权限访问的图谱 JSON。自动化测试通过 `ATLAS_DB_FILE` 使用独立临时数据库。

## 架构与扩展

```
src/lib/model.ts       知识数据契约与发布前校验
src/lib/seed.ts        示例内容
src/lib/storage.ts     SQLite、旧 JSON 迁移、图谱归属与事务
src/lib/diff.ts        发布前与历史变更清单
src/lib/auth.ts        服务端维护权限与同源校验
src/app/api/atlas      内容、草稿、发布、反馈接口
src/app/api/atlases    图谱创建、列表、复制与可见性设置
src/app/api/session    维护会话
src/components/Atlas   视角、探索状态与图谱交互
src/components/AtlasLibrary 图谱空间与个人作品设置
src/components/GraphCanvas 图谱内部测量与拖动状态
src/components/SpectralEdge 动态边界连接，避免固定端点反向绕线
src/app/globals.css    光谱主题、响应式与视觉层
```

节点语义、关系与视觉坐标分开存储；个人布局覆盖默认坐标。维护编辑永远通过服务端权限校验。三图共享一组带身份的节点与关系，切换视角保留焦点，由显式关系引导进入其他维度。

后续建议把 Atlas 拆分为视角选择器、图谱渲染器、详情面板与维护编辑器；为棱镜引入独立 `PrismConfig`（视角、关系筛选、展开深度、布局），改变查询与呈现，不直接修改公共关系。Motion/SVG 可接管转场与光路，PixiJS 可作为独立光效层。当前未实现真实光学模拟、棱镜摆放、AI问答、多人同步或云端部署。

## 第三阶段：知识棱镜与偏折镜

知识节点本身呈现为棱镜，每张地图有一个个人光源（默认典型任务或首个节点，可用「设为光源」调整）。默认「色散」只显示当前维度的关系；选择知识后切换「折射」，保留光源到该节点的最短连通上游路径与该节点的跨图关联，隐藏无关分支。找不到路径时明确提示，不补造关系。

光线箭头表示从光源出发的探索方向，不改动关系的原始语义方向。关系含义与依据仍可点击查看。

选择光线后点击「＋ 偏折镜」，可把镜子放到这条光路上。选中镜子后，可以直接把右侧出射点拖到目标节点（35px 吸附范围），或点击「选择目标棱镜」再点击节点；底部下拉选择也会立即切换实际连接。镜面角度自动根据入射与出射方向计算，移动镜子后仍保持连接。选中的预览目标会保存在个人探索中，可用「还原原光路」撤销；不再提供自由旋转猜目标的操作。有编辑权限时，「重定向为关系草稿」会要求重新填写关系名称与依据，确认后才替换该关系的草稿，正式版本仍须审核发布。访客也可摆放镜子探索，但不能修改他人的知识图谱。

「保存探索／恢复探索」保存光源、焦点、滤光片、模式、棱镜位置及镜子布局，按图谱隔离存于当前浏览器。每条关系在一个观察模式下可放置一面镜子；支持多条关系各自放置镜子。当前不模拟多镜面连续碰撞、真实光线追踪或波动光学。旧的独立棱镜筛选控件已移除。
