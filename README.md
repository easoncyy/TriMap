# TriMap · 光谱 Spectrum Atlas

TriMap 是一个以光谱为视觉语言的本地知识图谱原型。项目围绕「面向机器人操作的具身视觉」组织知识，通过领域、生态、认知三张相互关联的地图，帮助使用者探索概念、研究资源与判断依据。

当前内容是用于验证结构和交互的演示样例，尚需团队核实和扩充。项目支持本地创建、浏览和维护多份图谱；它不是已经部署的公共服务。

## 交互概念

| 概念 | 在项目中的含义 |
| --- | --- |
| 滤光片 | 切换领域、生态、认知三种知识视角 |
| 光源 | 当前探索的起点，可以选择知识节点作为光源 |
| 知识棱镜 | 每个知识节点；选中后查看详情和相关知识 |
| 关系镜 | 每条可见关系的交互载体；选中后查看关系、依据和反馈 |
| 色散 | 探索当前地图内的关系 |
| 折射 | 从选中的知识出发探索跨地图关系，同时保留可达的上游光路 |
| 光线 | 表现知识流的视觉连接；方向用于引导探索，不改变关系原有语义 |

切换到折射时，如果从光源找不到已选节点的路径，界面会提示，不会虚构关系。关系镜可拖动调整，并可通过拖动出射点或选择目标来预览重定向。预览只影响个人探索；有编辑权限的用户需要确认关系名称和依据、保存草稿并审核发布，才能修改正式知识关系。

## 快速开始

需要 Node.js 24 或更新版本。项目使用 Next.js、React、TypeScript、React Flow 和 Node.js 内置 SQLite，无需安装独立数据库服务或配置外部模型密钥。

```powershell
git clone https://github.com/easoncyy/TriMap.git
cd TriMap
npm ci
npm run dev
```

打开 http://127.0.0.1:3000 。开发服务默认只监听本机。生产模式可运行 `npm run build`，再运行 `npm run start`。

维护者入口的默认本地口令为 `local-spectrum`。复制 `.env.example` 为 `.env.local` 并设置 `MAINTAINER_PASSWORD` 可修改口令，重启服务后生效。这只是本地原型的共享维护身份；对外部署前还需要正式身份管理、限流、HTTPS、备份和合适的部署方案。

## 浏览与维护

- 顶部滤光片切换三张地图；底部工具栏提供搜索、列表、反馈和布局等操作。选择节点或关系镜后，可查看相应详情。
- 点击「自动布局」可按光源与连接层级排列知识棱镜，并为关系镜选择偏离直线的位置。它是启发式布局，复杂图谱仍可能交叉，可继续手动调整。
- 「保存探索／恢复探索」在当前浏览器中按图谱保存光源、焦点、色散／折射模式、节点与关系镜位置；探索状态会自动保存在本机，存档用于回到手动保存的那一版。个人探索与正式知识内容分开保存。
- 通过「图谱空间」浏览同一服务实例中的公开图谱，创建空白图谱或复制当前已发布内容。新图谱默认私有，发布内容与设置公开是两个独立操作。
- 访客与维护者都可以针对节点或关系提交具体反馈。图谱所有者及维护者可以编辑内容、管理关系、处理反馈、审核发布并查看或恢复版本。
- 编辑先进入草稿；审核时查看变更并填写更新原因，发布后才更新可见的正式内容。恢复历史版本也先进入草稿。

访客通过服务端签名的 HttpOnly Cookie 识别自己的图谱。清除 Cookie、切换浏览器或使用不同主机名可能导致原归属身份无法使用；目前没有账号恢复或跨设备同步。公开署名和反馈内容会展示给能够访问该图谱的人。这里的「公开」指在同一个服务实例内可发现，并不代表自动发布到互联网。

## 数据与备份

首次访问时，应用在 `data/atlas.sqlite` 初始化数据库和共享样例。每份图谱的知识、草稿、反馈和历史分别保存，使用 SQLite 事务更新。若首次迁移时发现旧版 `data/store.json`，会在数据库尚无共享图谱时导入，保留原文件；之后以 SQLite 为准。`data/` 不纳入 Git。

备份时先停止所有使用数据库的服务，再复制整个 `data/` 目录，包括可能存在的 WAL 文件。也可以从界面导出当前有权限访问的图谱 JSON。多人并发编辑冲突处理及跨设备身份管理仍需后续完善。

## 应用层内容

`src/lib/application-content.ts` 包含 20 张应用侧知识卡片和 25 条关联，围绕任务边界、场景检索增强、可供性、开放词汇目标定位、示教数据覆盖、Sim-to-Real、长程任务、人工接管与载体适配，连接数据集、任务基准和认知方法。正文直接解释术语及其应用条件；「待核实」表示编辑审核状态，不代表概念尚未定义。算法和基础设施的内部实现留给相应专题。

这批卡片会进入新建数据库的共享样例。已有 `data/atlas.sqlite` 不会因更新种子而自动覆盖，维护者应在现有图谱中核对后通过草稿与发布流程纳入内容，以保留已有编辑、反馈与版本历史。

## 项目状态

三种视角、关系引导、基础维护流程、光学隐喻和自动布局已有本地原型。内容准确性、真实用户理解效果与完整维护流程仍需要团队验证。自动布局不保证密集图谱完全无交叉；光线与镜面是交互表达，并非真实光学模拟。复杂艺术动画、多人实时协作和互联网部署仍可在后续版本探索。
## 布局与可读性

各地图首次打开时，为尚无个人坐标的节点生成围绕光源的环形布局；已有拖动位置保留。可以点击「自动布局」重新排布当前视图。切换滤光片保留已保存的知识位置与折射布局。

标签固定绑定在各自棱镜或关系镜附近，随物体整体移动，不再独立搜索远处空位。缩小时最多 4 倍补偿，标题最多两行；完整内容在详情中查看。自动布局扩大间距，并考虑固定标签区域与光线的碰撞代价，尽量减少遮挡。极密图谱仍可手动微调。

## 材质与视觉状态

`public/materials/fabric/` 收录 ambientCG Fabric041 的 CC0 材质包，来源与使用说明见 `public/materials/README.md`。桌面使用本地颜色纹理并进行深色调色；棱镜、光源、关系镜和分类卡使用 SVG/CSS 的高光、厚度和投影表现。

当前未接入物理渲染器，法线、粗糙度与位移贴图尚未参与渲染；拟物艺术效果仍待完善，不能将本轮材质调整视为已通过审美验收。当前已通过类型检查、31 项核心测试、3 项 Cloudflare 测试、Next.js 和 Pages 构建及本地维护流程集成测试。本地浏览器已验证 Infra 入口、镜面展开/收起、刷新恢复及固定标签；密集场景仍可能局部重叠。

## AI Infra 知识与逐层探索

点击底部「AI Infra」定位实时推理系统入口。13 张 Infra 卡片跨领域、生态、认知三图，包含延迟、内存、精度、调度、实时性、评测、TensorRT/Triton/ROS 2 资源和待验证问题；来源见卡片的官方文档链接，状态为待核实。

色散默认从当前光源展示最多两个关系跳数；折射从当前选中知识展示两跳跨维度邻域。超出边界的知识保留为可展开的真实关系镜：点击 + 只打开该关系后一个知识节点，点击 − 收起该路径。其他路径仍可达的共享节点保留；「收起至两层」恢复当前视图默认状态。折叠仅改变个人探索，不删除真实关系，状态按图谱、模式与起点存于浏览器，并进入探索存档。搜索和维护连线可查看完整内容，避免折叠妨碍定位及编辑。

标签固定跟随所属物体，缩放只补偿字号、不再全局挪动；自动布局考虑固定标签区域。光路演示系统地图已停用，迁移仅删除指定系统演示，不删除个人副本。

## 分支布局与关系显示

自动布局改为双侧树形分支：同一主分支占用独立纵向区间，关系镜在支路通道中避让，折叠镜使用外侧分栏，不挤在父节点周围。默认「主路径」为所有可达节点保留一条路径，额外关联可在详情查看或切换「全部关系」显示。关系名称仅在悬停/选中其镜面时显示，并高亮对应光路；节点标题常驻，缩放时字号补偿。

布局版本升级时先把旧探索状态备份到浏览器 `spectrum-layout-backup:<图谱ID>`，再重新计算旧自动布局；可用「恢复旧布局」找回。旧版本没有手动坐标标记，因此不能自动区分旧的手动与自动位置。升级后单独记录拖动位置，自动展开保持这些位置；显式「自动布局」可重新排布当前视图。

本地浏览器验证了主路径/全部关系切换不删除节点（12 个节点保持不变，光路段 29→33）、展开到 13 个节点；该场景 13 个节点标题的实际屏幕包围盒无相互重叠。密集自定义图和手动布局仍可能需要调整，不保证任意图零交叉。


### 折叠时保持空间位置

展开／收起关系镜只改变可见内容，不重新挂载画布或自动适配视野。已出现的棱镜、自动关系镜及手动位置都会保留；新出现的知识在已有位置之外增量放置。收起后重新展开恢复原位置，色散与折射均适用。需要全图重排时显式使用「自动布局」。探索存档同时保留自动位置，折叠不修改知识数据。
